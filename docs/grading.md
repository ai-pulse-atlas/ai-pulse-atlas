# 影响力分级标准（S / A / B / C）

模型类事件（`category` 为「模型」）按下文「模型类：能力 × 规模」判定；其他品类沿用下面的标准表和兜底打分。

| 等级 | 典型事件 | 月度目标数量 | 指数权重 |
|---|---|---|---|
| **S** | 头部厂商新一代旗舰；明确登顶主要榜单；≥100 亿美元的融资/并购；全行业级监管或出口管制生效 | 0–3 | 8 |
| **A** | 头部厂商重要小版本；二线厂商旗舰；开源 SOTA；新一代芯片；≥10 亿美元融资；主流产品重大功能；重大诉讼判决 | 若干 | 4 |
| **B** | 常规更新；1 亿–10 亿美元融资；有代表性的开源项目/论文 | 不限 | 2 |
| **C** | 其余 | 不限 | 1 |

「头部厂商」名单见 `entities.yaml` 中 `tier: 1` 的条目。模型类不再因厂商层级或版本代际直接定级，厂商层级只作规模旁证。

## 硬性规则

1. **非官方确认的事件最高 B**：`verified` 不是 `official` 时，`impact` 只能是 B 或 C（校验脚本强制检查）。
2. **拿不准就降一级**。
3. 每条事件必须写 `impact_reason`，一句话说明为什么是这个级别。
4. 级别调整不删旧值，追加到 `impact_history[]`：必填 `from`、`to`（S/A/B/C）、`at`（有效北京时间，ISO 格式且时区为 `+08:00`）、`reason`（非空字符串）；可选 `ref`（http:// 或 https:// 链接，不含空白）、`by`（maintainer/bot/community），禁止未知字段。记录按 `at` 严格升序（不得同时间），相邻记录上一条 `to` 等于下一条 `from`，末条 `to` 等于当前 `impact`；校验脚本强制检查。

## 模型类：能力 × 规模

适用于 `category` 为「模型」的事件，与上面的标准表冲突时以本节为准。能力和规模各分 0–4 档，按矩阵得出等级。

### 能力档 Cap（0–4）

以独立第三方证据为主；单凭官方自评不能到 Cap3 及以上。

| 档 | 条件（满足任一） |
|---|---|
| **4** | 主流独立榜单登顶（LMArena Text Overall #1，或 Artificial Analysis Intelligence Index #1，注明推理档位）；或 ≥2 个独立公开基准同时刷新 SOTA，且有第三方复现或榜单页。单一官方「SOTA」不算 |
| **3** | 至少一张主流独立榜单进入前 5；或相对上一代在 ≥2 个公开基准大幅跃迁，且有第三方分数 |
| **2** | 有独立分数但处于中游；或相对自家上一代有明确提升、未进前 5 |
| **1** | 只有官方描述或内部评测，查不到独立榜单 |
| **0** | 能力主张无法核对 |

- Flash / Mini / Haiku 等轻量型号：绝对能力与性价比（同价位/同延迟最优）分开看。只是性价比登顶，Cap 最高 3。
- 开源权重 / 中小厂：同样看独立榜单。开源权重类别第一（如 Artificial Analysis 开放权重榜 #1）最高 Cap3，除非同时登顶不限开放的总榜。

### 规模档 Scale（0–4）

| 档 | 条件 |
|---|---|
| **4** | 成为大众主力产品的默认或主推模型（如 ChatGPT、Gemini 免费版、Claude.ai 的默认模型），或有可核查的亿级月活/调用证据 |
| **3** | 全面 GA：公开 API，且进入至少一个主力付费消费端产品供一般用户自选 |
| **2** | API 公开预览或 GA；或开源权重可下载且有实质采用（多推理平台上架、有代表性产品接入等） |
| **1** | 仅受信客户 / 邀请制 / 受信计划；或已宣布但权重未放 |
| **0** | 只有新闻或论文，没有可调用通道 |

默认模型身份变化快，没有官方写明「default」或可核查数据时不给 Scale4。

### 组合矩阵

| Cap \\ Scale | 4 | 3 | 2 | 1 | 0 |
|---|---|---|---|---|---|
| **4** | S | S | A | A | B |
| **3** | S | A | A | B | B |
| **2** | A | A | B | B | C |
| **1** | B | B | B | C | C |
| **0** | B | B | C | C | C |

### 模型类附加规则

1. **预览最高 A**：`status` 为 `preview` 或 `announced`，或明确只对受信 / 邀请 / 内部开放时，不得为 S；范围极窄且没有公开 API 时可再降到 B。
2. **版本号不直接决定 S**：不能只因新一代编号或旗舰命名给 S。
3. **模型类停用四维兜底打分**，档位拿不准时按「拿不准就降一级」取较低等级。
4. `impact_reason` 用一句话写明 Cap、Scale 和关键证据（榜单名次或可用范围），例如 `Cap4(LMArena Text #1)+Scale3(API GA+付费端全量)`。
5. **临时级与复核**：发布当日按当时可得证据定级；证据不足时在 `impact_reason` 或 `note` 中注明 `provisional`，并在 `note` 写 `review_due`（预览或无独立榜单为事件日 +7 天，开源权重与采用数据为 +30 天）。复核后级别有变，改 `impact` 并按硬性规则第 4 条追加 `impact_history`，不改历史条目；`reason` 写明 Cap/Scale 依据，有证据链接时填 `ref`。

## 兜底打分（非模型类，标准表覆盖不到时）

四个维度各 0–3 分，合计：

| 维度 | 0 | 1 | 2 | 3 |
|---|---|---|---|---|
| 影响范围 | 小圈子 | 单一细分领域 | 一个大领域/大量开发者 | 全行业/大众 |
| 能力跃迁 | 无 | 小幅 | 明显 | 代际 |
| 资本信号 | 无 | <1 亿美元 | 1–10 亿美元 | >10 亿美元 |
| 持续性 | 一次性 | 数周 | 数月 | 长期结构性 |

合计 ≥10 → S；7–9 → A；4–6 → B；≤3 → C。
